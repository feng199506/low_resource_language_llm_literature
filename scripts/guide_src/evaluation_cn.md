# 评测学习与设计指南

目标：为小语种模型或应用建立可信的评测体系。

先厘清五组容易混淆的概念：
1. 原生语言测试与翻译测试：基准是用目标语言原生编写的，还是从英语翻译来的。
2. 用小语种回答与用该语言正确推理/执行工具：前者只说明输出语言对，后者才说明推理与操作正确。
3. 机器翻译文本与自然产生的本地语言文本。
4. 作者自报结果与独立复现结果。
5. 通用方法证据与特定语言案例证据。

每篇论文的这几项属性，见 `catalog_cn.csv` 中“基准来源（原生/翻译）”“结果来源”“证据范围”“关键区分说明”几列。

翻译基准的问题与改进：
- 〔LRL-P-15-001〕Global MMLU：标注翻译基准中的文化偏差。
- 〔LRL-P-15-007〕The Bitter Lesson Learned from 2,000+ Multilingual Benchmarks。
- 〔LRL-P-15-013〕Global PIQA。

文化知识：〔LRL-P-15-003〕BLEnD。

构建原则（来自上述文献的共同建议）：
- 优先母语者编写或改写。
- 翻译题须经母语者审校，并标注文化不适用的题目。
- 公开题目时说明来源与许可。

建议：

- 评判模型对目标语言不流利时，评判结果不可靠（见〔LRL-P-10-009〕）。

建议：
- 小语种测试集通常规模小，应报告置信区间或多次运行的方差。
- 不同语言之间的分数差，若在误差范围内，不应解读为能力差异。

## 8. 回归测试工程

- 〔LRL-E-18〕lm-evaluation-harness：支持多语言任务配置。
- 〔LRL-E-19〕lighteval。
- 建议把以下几类评测固定为版本化的回归集，在每次训练或部署前运行：
  - 目标语言评测；
  - 原有语言评测；
  - 代码评测；
  - 工具调用评测；
  - 安全评测。
