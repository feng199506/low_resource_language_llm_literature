# 应用开发学习与设计指南（路线 B：现有模型 + 本地知识库 + 检索与工具）

本指南把三条应用路线分开整理：对话助手、知识库问答、编程助手。每条路线都区分两类内容：
- 模型能力：模型本身在目标语言上能做到什么，靠评测证明。
- 产品工程：检索、记忆、界面、隔离、监控等系统设计，靠工程实现与用户研究证明。

论文中的部署案例多为作者自报，场景、语言与用户群体各不相同，不能直接推广。

## 路线 1：对话助手

### 模型能力层
- 先用 evaluation_cn.md 的方法确认三点：
  - 基座在目标语言上的流畅度、事实性与安全性；
  - 对方言、罗马化书写、语码混合输入的鲁棒性；
  - 文化适切性。
- 罗马化与本文字差距：〔LRL-P-13-002〕Script Gap，印度语言医疗分诊。
- 跨语言临床正确性漂移：〔LRL-P-13-032〕，豪萨语与英语。
- 语码转换与方言：
  - 〔LRL-P-13-038〕BanglAssist。
  - 〔LRL-P-02-032〕LLM 对语码转换文本的理解。

### 产品工程层
- 真实场景部署与用户研究：
  - 〔LRL-P-13-001〕ASHABot：社区卫生工作者，印地语，含语音。
  - 〔LRL-P-13-021〕Farmer.Chat：农业服务，多种非洲及印度语言。
  - 〔LRL-P-13-006〕乌尔都语语音电子病历系统。
  - 〔LRL-P-13-041〕KumbhDoot：大型集会公共服务。
- 文化与用户需求：
  - 〔LRL-P-13-003〕重新设想孕产健康聊天机器人。
  - 〔LRL-P-13-054〕面向月经健康的以人为本设计。
- 教育：
  - 〔LRL-P-13-045〕AFRILANGTUTOR。
  - 〔LRL-P-13-044〕印度农村 K-12 教育中的 LLM（通用支撑）。
- 客服与任务型对话：
  - 〔LRL-P-13-040〕Telenor 北欧客服语料。
  - 〔LRL-P-13-052〕沃洛夫语任务型对话。
  - 〔LRL-P-13-059〕Multi3WOZ。
- 工程实现：
  - 〔LRL-E-32〕Open WebUI：对话前端，注意其许可证附加品牌条款。
  - 〔LRL-E-27〕smolagents。

库内缺口：
- 政务、客服的真实部署论文较少。
- “会话记忆”在多语言场景下的专门研究较少。
